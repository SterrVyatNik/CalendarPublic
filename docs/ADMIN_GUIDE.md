# Calendar 2.0 — руководство администратора

**Сайт:** https://calendar.sterrvyatnik-tracker.workers.dev/  

**Смена группы СПбПУ:** автоматически синхронизированные пары прежней группы скрываются во всех активных представлениях без удаления из базы. Отдельно импортированные пользователем личные события сохраняются. При возврате к прежней группе её автоматически сохранённые недели снова доступны.

**Полная очистка СПбПУ:** пользователь может самостоятельно нажать **Настройки → СПбПУ → Убрать все расписания СПбПУ**. После просмотра количества записей и подтверждения удаляются все автоматические и вручную импортированные пары только его аккаунта, группа и метки синхронизации; другие события, задачи и аккаунты не затрагиваются. Это необратимое удаление, поэтому перед действием рекомендован экспорт данных.
**Для пользователей:** [Руководство пользователя](USER_GUIDE.md)  
**О проекте:** [README](../README.md)

Это руководство описывает **управление пользователями через интерфейс сайта**. Развёртывание, исходный код и внутренние настройки сервера здесь не рассматриваются.

## 1. Роль администратора

Администратор может создавать учётные записи, сбрасывать временные пароли, завершать пользовательские сессии, блокировать или разблокировать доступ и удалять аккаунты после подтверждения. У администратора есть собственный личный календарь.

**Важно:** права администратора не дают доступа к чтению и редактированию личных задач других пользователей через обычную панель управления. У каждого аккаунта свои записи, прогресс и настройки.

## 2. Создание пользователя

1. Войдите в Calendar под учётной записью с ролью **Администратор**.
2. Откройте **Настройки → Администрирование → Пользователи**.
3. Введите уникальный логин и нажмите **Создать**.
4. Сразу сохраните показанный **временный пароль**: повторно посмотреть его нельзя.
5. Передайте пользователю логин, временный пароль и [ссылку на календарь](https://calendar.sterrvyatnik-tracker.workers.dev/) по защищённому каналу.
6. Попросите пользователя войти и сменить временный пароль.

**Логин:** от 3 до 32 символов: латинские строчные буквы, цифры, точка, дефис и подчёркивание. Первый символ — буква или цифра; пробелы и кириллица не поддерживаются.

Новые аккаунты получают обычную роль пользователя. Самостоятельная публичная регистрация на сайте не предусмотрена.

## 3. Управление учётными записями

Найдите пользователя в разделе **Настройки → Администрирование → Пользователи**.

| Действие | Что происходит |
| --- | --- |
| **Сбросить пароль** | Создаётся новый временный пароль; прежние сессии пользователя завершаются |
| **Завершить сессии** | Все действующие сеансы выбранного пользователя закрываются |
| **Заблокировать** | Запрещается вход до разблокировки, данные сохраняются |
| **Разблокировать** | Пользователь снова может войти |
| **Удалить полностью** | Учётная запись и связанные личные данные удаляются после дополнительного подтверждения |

### Если пользователь забыл пароль

Нажмите **Сбросить пароль**, скопируйте новый временный пароль и передайте его адресату. При следующем входе пользователь должен установить собственный пароль длиной от **12 до 128 символов**. Старый личный пароль администратору недоступен.

### Если устройство потеряно

Нажмите **Завершить сессии**. Если пароль также мог стать известен постороннему человеку, выполните его сброс.

### Если нужно временно ограничить доступ

Используйте **Заблокировать**, а не полное удаление. При разблокировке данные остаются на месте.

### Если пользователь просит удалить аккаунт

Полное удаление — **необратимое действие**. Сначала убедитесь, что пользователь согласен, и предложите экспортировать резервную копию. Затем используйте **Удалить полностью** и предусмотренное сайтом подтверждение логина. Не применяйте эту операцию для исправления обычных ошибок входа.

## 4. Резервный код администратора

Резервный код нужен для восстановления **вашего административного аккаунта** при потере пароля.

1. Откройте **Настройки → Администрирование**.
2. Найдите блок **Резервный код администратора**.
3. Нажмите **Создать новый код**.
4. Сразу сохраните код в безопасном месте, отдельно от пароля.

Код показывается при создании, предназначен для однократного восстановления и не должен публиковаться. Создание нового кода отменяет прежний.

Для восстановления на экране входа выберите **Аварийное восстановление**, укажите логин администратора, резервный код и новый пароль. После успешного восстановления создайте новый резервный код.

Если код оказался у посторонних, используйте **Отозвать код**.

## 5. Что может делать пользователь самостоятельно

Владелец аккаунта управляет собственными задачами, событиями, напоминаниями, расписанием СПбПУ, темой оформления, XP-настройками и резервными копиями.

Путь создания задачи: **Обзор → + Задача → название → время → длительность → Сохранить**. Напоминание для новой задачи рассчитывается автоматически, пользователь может поменять интервал или отключить его для отдельной задачи.

В **Настройки → Данные** пользователь может экспортировать JSON-резервную копию. Экспорт не включает пароли, действующие сессии или административные коды восстановления. Импорт предварительно показывает сведения о файле и добавляет записи без очистки текущего аккаунта.

Не путайте **Полный откат** в пользовательских настройках (очистка личных данных с сохранением аккаунта) и **Удалить полностью** в административной панели (удаление аккаунта).

## 6. Частые вопросы

**Не вижу раздел «Администрирование».** Проверьте, что вход выполнен под аккаунтом с административной ролью.

**Не получается создать пользователя.** Проверьте допустимые символы, длину логина и отсутствие уже занятого имени.

**Человек не может войти после создания аккаунта.** Проверьте правильность временного пароля и логина. При потере временного пароля сделайте сброс.

**Пользователь не видит расписание СПбПУ.** Попросите выбрать группу в **Настройки → СПбПУ**, проверить период и включённый источник расписания.

**XP-настройки одного аккаунта не влияют на другой.** Это ожидаемо: настройки наград индивидуальны.

**Пропал доступ к аккаунту администратора.** Используйте сохранённый резервный код. Если кода нет, обратитесь к владельцу сервиса; не пытайтесь обходить защиту.

## 7. Памятка при выдаче доступа

- [ ] Создать уникальный логин.
- [ ] Сохранить временный пароль в момент создания.
- [ ] Передать доступ лично или по защищённому каналу.
- [ ] Напомнить о необходимости сменить пароль.
- [ ] Отправить [руководство пользователя](USER_GUIDE.md).
- [ ] Проверить, что пользователь смог войти.
